Section 2

The Three Specialized Portals & Workflows

LegalEase enforces strict separation of concerns via three specialized portals. Each user is assigned a specific role (ROLE_CLIENT, ROLE_LAWYER, ROLE_ADMIN) that restricts both backend REST endpoints and frontend routing views.

1. Client Portal (`/client/*`)

Built for individuals and businesses seeking contract risk visibility before execution:

  • Document Upload: Drag-and-drop ingestion supporting PDF and DOCX formats up to 10MB. Files are sanitized and checked for malicious content.
  • Automated Threat Assessment: Generates an aggregate Risk Score (0-100) and categorizes clauses into High Risk, Moderate Risk, and Safe/Standard.
  • Interactive Contract Q&A Chat: Allows clients to query specific contract sections (e.g., "What is the notice period for early termination?") with contextual responses.
  • Contract Risk Trajectory: Interactive SVG curve tracking threat levels across historically uploaded agreements.

2. Lawyer Portal (`/lawyer/*`)

Designed for verified advocates to provide accredited redlines and legal assessments:

  • Bar Council KYC Verification: Advocates submit enrollment details, jurisdiction, years of experience, and proof of license. Documents are stored with AES-256 encryption.
  • Review Queue: Paginated listing of assigned and pending client documents awaiting expert evaluation.
  • Legal Redlining & Counsel Notes: Formatted workspace allowing lawyers to append legal annotations, add caveat warnings, and issue approved counter-clauses.
  • Advocate Profile Management: Manage legal specializations (Corporate, Intellectual Property, Employment, Litigation).

3. Compliance & Admin Portal (`/admin/*`)

Provides regulatory oversight, security telemetry, and user management:

  • User Lifecycle Governance: View all registered accounts, toggle account statuses (ACTIVE, SUSPENDED, DISABLED), and force password resets.
  • Advocate Verification Queue: Inspect pending bar certificates, verify enrollment IDs, and approve or reject lawyer access.
  • System Audit Trails: Immutable chronological logs capturing authentication events, document access, IP addresses, and user-agent fingerprints.
  • Suspicious Activity & IP Blacklist: Real-time detection of brute-force anomalies with manual and automated IP blacklisting capabilities.
  • Appeal Arbitration: Ingest and resolve formal account suspension appeals with document evidence review.
Section 3

Security Architecture & Cryptography Deep-Dive

Legal contracts contain sensitive corporate and personal information. LegalEase implements a defense-in-depth architecture adhering to OWASP Top 10 guidelines and SOC-2 data governance standards.

Authentication & Token Lifecycle

Authentication utilizes stateless JSON Web Tokens (JJWT 0.12.6) with cryptographic signing via HMAC-SHA256. Dual-token rotation separates short-lived access tokens (15 minutes) from long-lived refresh tokens (7 days).

15-Minute Brute-Force Account Lockout

Automated Lockout Policy
5 consecutive failed password submissions automatically lock the account for 15 minutes. Even if the correct credentials are provided during this window, the server returns HTTP 423 LOCKED with remaining freeze duration.

Distributed Sliding-Window Rate Limiting (Redis)

Configured in application.properties to mitigate credential stuffing and denial-of-service:

Action / Endpoint Threshold Sliding Time Window Violation Consequence
User Login 5 attempts 10 Minutes HTTP 429 / Account Lockout Warning
User Registration 3 attempts 1 Hour IP Temporary Throttling
Document Upload 10 uploads 1 Hour Upload Suspension
General REST APIs 100 requests 60 Seconds HTTP 429 Too Many Requests

Cryptographic Storage (AES-256)

Bar Council licenses, certificates, and confidential legal notes are protected at rest via AES-256-GCM authenticated encryption. Encryption keys are managed independently of the database schema via environment variable injection (`AES_SECRET_KEY` and `AES_FIELD_KEY`).

Client Fingerprinting & Email Dispatch

Each authenticated request evaluates client IP (resolving X-Forwarded-For headers) and device user-agents. When a login originates from an unrecognized fingerprint, the system asynchronously sends a security alert email detailing IP location, timestamp, and device details.

Section 6

Key Engineering Challenges & Bug Resolutions

1. The `documents.filter is not a function` Admin Error

Symptom: Logging into the Administrator dashboard triggered an immediate React crash modal stating TypeError: documents.filter is not a function.

Root Cause: Spring Data JPA repository endpoints returning Spring Pageable objects wrapped responses inside a { content: [...], pageable: {...} } envelope. When the frontend attempted documents.filter(...) directly on the response payload, JavaScript threw a TypeError because the object was not an Array.

Defensive Resolution: Implemented defensive array unwrapping across all table components and state initializations: 

// Defensive normalization pattern applied across all portal views
const rawData = response?.data?.data;
const safeList = Array.isArray(rawData) 
    ? rawData 
    : (rawData?.content || []);
setDocuments(safeList);

2. Elimination of Marketing Navbar & Portal Collision

Symptom: The top marketing navigation bar was rendered concurrently with the fixed left sidebar, causing navigation links to collide and rendering the left side messy and unusable.

Resolution: Encapsulated all 20+ portal routes inside <DashboardLayout>, which renders a dedicated dashboard top bar with breadcrumbs and user badges, completely omitting the landing page navbar.
